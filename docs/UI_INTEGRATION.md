# Подключение интерфейса к сервису

Интерфейс первоначально построен по `ForecastService` из ревизии `6d32813` и перенесён поверх актуального интеграционного слоя `59ab693`. Общие схемы и сервис принадлежат участнику 1 и сохранены без изменений. Адаптер — `frontend/gateway.py`.

Устанавливать UI совместно с общим lock: `python -m pip install -r requirements.lock -r frontend/requirements.txt`. UI закрепляет Streamlit 1.64.0: исходная версия 1.55.0 требовала pandas<3 и конфликтовала с pandas 3.0.6 основного проекта. Общий lock не изменён.

## Существующие вызовы

| Действие UI | Вызов backend |
| --- | --- |
| Каталог доступных выпусков | `service.list_forecasts(mode=mode)` |
| Показ выбранной версии | `service.get_forecast(forecast_id)` |
| Запрос расчёта | `service.create_forecast(ForecastRequest(...))` |
| Сравнение версий | `service.compare_forecasts(first_id, second_id)` |
| Журнал к времени просмотра | `service.events(as_of=datetime)` |
| Готовый CSV | `service.export([forecast_id], strict=True, release_policy="all")` |

Backend получает `origin_time`, две `turbine_ids`, `horizon_hours` 24/48 и `mode`. UI не передаёт погодный run: его выбирает сервис. Локальный просмотр читает готовые fixtures через отдельный `FixtureService`, выбранный только при `mode=fixture`.

`ForecastResult.predictions.rows` преобразуется в список для визуализации. Поля `manifest.weather` и `manifest.model` дают происхождение, время доступности и версию модели. `manifest.last_actual_available_at` используется только как метаданные свежести, а не как фактическая мощность.

## Реализованное дополнение к service.py

Новые выпуски сохраняют почасовую погоду в manifest. Для погоды и доступного факта реализован метод:

```python
def get_display_context(self, forecast_id: str, *, as_of: datetime) -> dict:
    ...
```

Форма ответа:

```json
{
  "weather": [
    {
      "turbine_id": "turbine_1",
      "valid_time": "2026-01-16T00:00:00Z",
      "wind_ms": 7.2,
      "temperature_c": -4.0,
      "direction": "СЗ",
      "condition": "Облачно"
    }
  ],
  "actuals": [
    {
      "turbine_id": "turbine_1",
      "target_start": "2026-01-16T00:00:00Z",
      "target_end": "2026-01-16T01:00:00Z",
      "available_at": "2026-01-16T01:15:00Z",
      "power_norm": 0.42
    }
  ],
  "metrics": null
}
```

Числа выше — пример формы, не реальные измерения. `condition` и `direction` необязательны: UI не выводит их из температуры или скорости. Погодные значения должны относиться к `run_id` сохранённого выпуска и быть доступными к его `origin_time`; текущий live-прогноз не подходит. `valid_time` отображается в UTC. Backend должен разрешать только доступный к `as_of` факт с завершёнными часовыми интервалами. UI дополнительно повторяет эту проверку перед отображением.

Без метода поля остаются пустыми. UI не обходит сервис ради чтения `store`, CSV или weather-кэша. Метрики пока не отображаются отдельной карточкой: после реализации `EvaluationReport` требуется согласовать её поля и период оценки.

## Каталог и виртуальное время

Дата и версии берутся из сохранённых выпусков, не из календаря с выдуманным покрытием. У native-адаптера начальное время просмотра равно `origin_time`; каталог предлагает просмотр через 12 часов и после завершения горизонта. Появляются только фактически доступные измерения. Fixtures содержат два дополнительных момента просмотра: +12 и +54 часа. Смена режима очищает текущие данные. Работа с отсутствующим сервисом никогда не включает fixture автоматически.

Для запуска с полностью настроенным сервисом предпочтителен `TWINTURBO_SERVICE_FACTORY=module:factory`. Для просмотра существующих результатов достаточно `TWINTURBO_CONFIG`. `TWINTURBO_PREDICTOR=module:factory` нужен только для расчётов. Модуль и фабрика — доверенные параметры оператора; UI не принимает их из веб-формы.

## Экспорт и объяснения

Экспортируется готовый артефакт backend, без пересчёта и самостоятельной сборки CSV. Текущий UI скачивает полный выбранный выпуск для обеих турбин; фильтр экрана 24/48 часов не фильтрует артефакт. Синтетические fixtures скачиваются только как `DEMO_ONLY_*.csv`, конкурсный путь заблокирован и в контроллере, и в fixture-адаптере.

Advisor формирует текст из готовых полей и явно сообщает об отсутствии факта или интервала. Никаких причинных диагнозов, новых прогнозов, скрытых метрик или вызовов LLM.
