# Проверка интерфейса TwinTurbo.ai

Проверено 23 сентября 2026 года на Python из рабочего окружения Codex. Использовался локальный сервер `python -m frontend.preview --port 8765`, общий с Streamlit frontend и контроллер.

## Автоматические проверки

`python -m unittest tests.test_ui_contract -v` — **20 проверок прошли**. 19 проверок интерфейсного контракта используют только стандартную библиотеку; дополнительная проверка использует реальные `ForecastResult` и `export_csv` с установленным Pydantic. Без Pydantic только эта дополнительная проверка пропускается явно.

Покрыты: выбор турбины и 24/48 часов, скрытие будущих фактов и незавершённых интервалов, отказ поздней погоды, null/zero, отсутствие квантилей, недопустимые временные метки и интервалы, неизменность старого выпуска, пересечение часов в сравнении, точные байты готового CSV, запрет конкурсного fixture-экспорта, отказ и восстановление, отсутствие скрытого fallback, отсутствие неподтверждённых диагнозов Advisor, преобразование backend-схемы и скрытие внутренних исключений.

Дополнительно: компиляция Python-модулей; `node --check frontend/assets/dashboard.js`; `git diff --check`.

## Проверка в браузере

- Стартовый экран, Canvas-площадка, турбины и график отображаются.
- Клик по второй турбине и выбор 24 часов меняют соответствующие данные.
- Продвижение времени просмотра на 12 часов открывает 10 уже доступных фактических часов; будущие скрыты.
- Сравнение исходного и обновлённого выпуска содержит 42 общих часа на горизонте 48.
- Отказ погоды убирает результат, повтор восстанавливает его.
- Replay без настройки сервиса показывает отказ, не синтетический результат.
- Готовый CSV скачан через окно «Экспорт готов»; событие скачивания подтверждено браузером.
- Мобильная ширина 390 px: колонки перестраиваются, горизонтальной прокрутки нет.
- Переключение на январь показывает снежный участок; анимация отключается кнопкой и учитывает `prefers-reduced-motion`.

## Проверка после переноса в основной проект

23 сентября 2026 года интерфейс перенесён поверх `59ab693`, без замены сервиса,
схем, хранилища, моделей и погодного модуля старой версией из ZIP.

- Windows / Python 3.12: общий `requirements.lock` и Streamlit 1.64.0 установлены
  совместно; `python -m pip check` не обнаружил конфликтов. Streamlit 1.55.0
  из исходного UI несовместим с pandas 3.0.6, поэтому обновлена только зависимость UI.
- `python -m pytest -q -p no:cacheprovider`: **48 passed**, без пропусков.
  Старый пример для проверки backend-экспорта дополнен полным manifest и хешем
  идентичности, которые требует актуальный экспорт. Проверки backend не ослаблены.
- Добавлен тест настоящего `ForecastService` и SQLite с синтетическими входами:
  два выпуска, 84 общие строки сравнения, неизменность первого выпуска, чтение
  без predictor, готовый CSV и запрет будущих данных/конкурсного fixture-экспорта.
- AppTest проверяет запуск `app.py` и штатную кнопку скачивания Streamlit.
- Offline-сценарий `prepare_demo.py --fixture`: 3 выпуска, 288 строк прошли
  `windoracle verify`; экспорт scheduled-выпусков содержит 192 строки.
- Streamlit запущен в браузере. Проверены выбор турбины и 24 часов, отображение
  отказа погоды и восстановление. Обработка действий перенесена в callback до
  отрисовки, чтобы компонент получал актуальное состояние в том же проходе.
- В Streamlit готовые байты CSV выдаёт штатная кнопка `st.download_button`;
  событие скачивания подтверждено браузером. Локальный preview сохраняет своё
  окно экспорта.

## Границы проверки

Обученные модели, исходные CSV и погодный кэш отсутствовали в репозитории на момент интеграции. Реальный численный прогноз, полный backend replay и качество модели этим UI-тестированием не подтверждаются.

## Улучшения интерфейса поверх общего релиза 0387601

23 сентября 2026 года сохранены изменения команды из 0387601: почасовая погода,
факт as-of, исправленный возраст погодного run и дополнительные моменты просмотра.
Новые изменения ограничены интерфейсом, его тестами и документацией.

- Полный набор: **102 passed**, включая 27 проверок UI; `pip check` — без конфликтов.
  Использовались Windows / Python 3.12, актуальный общий lock и установленный пакет.
  Полный запуск выполнен вне ограниченной среды с отдельным `--basetemp` внутри
  `outputs`: первоначальная проверка задержалась на импорте SciPy, а общая
  временная папка pytest оказалась недоступна из другого контекста запуска.
- Offline-сценарий с явным `--fixture`: 3 выпуска / 288 строк прошли verify,
  CSV scheduled-выпусков содержит 192 строки. Артефакты: `outputs/ui-release-smoke`.
- Новые проверки покрывают сводку сервиса при пустом каталоге, подключённую и
  отсутствующую модель, неизвестную погоду, запрет расчёта в демо, очистку старых
  статусов после отказа, проверку момента/горизонта и выбор первого рассчитанного
  выпуска. Последний сценарий использует явно обозначенную имитацию границы сервиса.
- Streamlit проверен в браузере на ширине 1440 и 390 px: русские названия и
  пояснения режимов, статусы подключения, календарь с недоступными пустыми датами,
  выбор месяца и времени, переход к следующему сохранённому выпуску, две линии
  сравнения на 42 общих часах и раскрываемая таблица. Компоновка стала компактнее.
- Проверены отсутствие подстановки демо в рабочие режимы и объяснения статусов.
  Скачивание готового CSV подтверждено событием браузера.
- Исправлена блокировка действий после экспорта или выбора того же выпуска:
  Streamlit отправляет подтверждение каждого действия даже при неизменном
  содержимом экрана. AppTest проверяет подтверждение экспорта; в браузере после
  закрытия окна скачивания проверены календарь, повторный выбор и следующий выпуск.
- JavaScript прошёл синтаксическую проверку; `git diff --check` не нашёл ошибок.

Эта проверка подтверждает работу UI и совместимость с сервисом. Реальные выпуски
общего релиза описаны командой отдельно в [RELEASE_CHECK.md](RELEASE_CHECK.md);
долгосрочное качество модели и полный погодный архив здесь не переоцениваются.
