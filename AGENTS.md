# Работа с WindOracle

Это каркас без реализованных функций. Пустые файлы намеренны.

1. Прочитать README.md, TEAM.md и docs/CONTRACTS.md перед реализацией.
2. Работать в пределах назначенной роли и её файлов. Если роль не указана, уточнить её до изменения чужих компонентов; чтение разрешено.
3. Общие схемы, зависимости и конфигурацию меняет участник 1 после согласования с командой.
4. Все данные модели поступают через снимок as-of. UI получает результаты через service.py. Не создавать обходные пути к будущим данным.
5. Сохранять исходники и опубликованные прогнозы. Не заменять реальную погоду синтетикой; fixture использовать только в явно обозначенном режиме.
6. Не реализовывать собственный дубликат чужого компонента. Запросить изменение контракта или работать с согласованным fixture.
7. Файлы agents содержат оркестрацию и вызовы общих функций; математика живёт в models, хранение в store, загрузка в weather. Не копировать расчёты между слоями.
8. При добавлении новых файлов обновлять таблицу владения TEAM.md. Изменение чужого файла согласовывать с владельцем.
9. Зависимости и команды проверять перед заявлением работоспособности. Пустые тесты не считаются пройденной проверкой.
10. README обновляет участник 3 по подтверждённым результатам команды. Не заявлять несуществующий деплой или неподтверждённые метрики.

Git-ветки и отдельные worktree/клоны создаёт команда в своём репозитории. Этот архив не содержит настроенного remote и не разделяет рабочие директории автоматически.
