# TwinTurbo.ai

**Почасовой прогноз мощности двух ветровых турбин на 24–48 часов — с историей выпусков, происхождением данных и журналом действий агентов.**

Проект ChachMechanics для HackAlem AI. Интерфейс показывает сезонную площадку с двумя кликабельными турбинами, прогноз и доступный на выбранный момент факт. Математика, выбор погодного run и экспорт принадлежат общему сервису.

## Что работает сейчас

- Интерактивный интерфейс в `frontend/`: земля, трава/снег, четыре сезона, вращение турбин и атмосферная анимация. Это условная схема, не географический или аэродинамический двойник.
- Выбор турбины, сохранённого выпуска и горизонта 24/48 часов. Даты берутся из каталога данных.
- Почасовой график нормализованной мощности, готовые Q10/Q50/Q90 и доступный факт. Пропуски и отсутствующие интервалы не заменяются числами.
- Погодная карточка, run, свежесть входов, версия модели и паспорт выпуска.
- Сравнение двух выпусков по совпадающим целевым часам; старый выпуск сохраняется.
- Журнал действий, объяснения Advisor, понятные отказы и повтор запроса.
- Скачивание готового CSV полного выпуска для обеих турбин. Выбранные 24/48 часов управляют экраном, экспорт не пересобирается интерфейсом.
- Адаптер к существующему `ForecastService` и Streamlit-точка входа `app.py`.
- Отдельный локальный просмотр без сторонних зависимостей на том же интерфейсе и контроллере.

**Данные демонстрации синтетические.** Включены 10 неизменяемых выпусков по 96 строк: две турбины × 48 часов, пять дат в разных сезонах, исходный и обновлённый выпуск. Это демонстрация интерфейса, а не доказательство качества модели или работающего погодного архива. Февральский пример не содержит факта и интервалов.

Финальная интеграция включает CSV → почасовой as-of снимок → настоящий NOAA GFS → обученную модель → 96 строк прогноза → SQLite/JSON/CSV → интерфейс. Базовая кривая, средний baseline, persistence, ridge, необязательный градиентный бустинг, bias и интервалы объединены. Проверка реальных выпусков выполнена на локальных исходных CSV и погодном кэше; сами данные и веса в Git не включены. Подробности слияния и проверки: [RELEASE_CHECK.md](docs/RELEASE_CHECK.md).

## Быстрый просмотр без установки библиотек

Из корня репозитория, Python 3.11 или новее:

```bash
python -m frontend.preview --port 8765
```

Открыть [локальный интерфейс](http://127.0.0.1:8765). Остановить сервер — `Ctrl+C`. Сервер привязан к `127.0.0.1`; это локальный просмотр, не публичный деплой. Интернет, API-ключи и исходные CSV для демо не нужны.

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.lock -r frontend/requirements.txt

```


Streamlit использует тот же HTML/CSS/JavaScript-компонент и тот же Python-контроллер, что и локальный просмотр. Сборка Node.js и внешние CDN не нужны. Общий `requirements.lock` теперь включает проверенные зависимости UI и ML.

**Проверка интеграции:** на Windows / Python 3.12 совместно установлены общий lock и Streamlit 1.64.0, pip check не обнаружил конфликтов. Все 102 теста прошли, включая запуск Streamlit через AppTest и работу UI-адаптера с настоящим сервисом и SQLite на явно синтетических входах.

## Сценарий работы

1. В режиме **Демо** нажать на турбину: изменятся данные справа, погодная карточка и график.
2. Переместить нижний ползунок: меняется сохранённый выпуск, его данные и сезон. Это дискретная шкала доступных выпусков; промежутки между датами не заполняются.
3. Выбрать **24 ч** или **48 ч** под сценой.
4. Открыть **Выпуск и время** для точного выбора выпуска, турбины и времени просмотра факта.
5. Нажать **Следующий выпуск**, затем вкладку **Сравнение**. UI открывает следующую сохранённую запись и показывает две линии на общих часах. Точные значения можно раскрыть под графиком.
6. В окне **Выпуск и время** продвинуть время просмотра на 12 часов: появится только уже доступный факт. Сам прогноз останется неизменным.
7. Открыть **Журнал агентов**, показать отказ погоды и восстановление через **Повторить запрос**.
8. Скачать CSV. В демо имя начинается с `DEMO_ONLY_`, строки содержат `mode=fixture`, `provenance=synthetic`. Конкурсный экспорт демо запрещён.

Кнопка **Вызвать расчёт через сервис** вызывает `ForecastService.create_forecast`. В fixture она возвращает сохранённый пример; в рабочем режиме нужен подключённый predictor. Подробный [сценарий показа жюри](docs/DEMO.md).

## Подключение реального сервиса

Установить общие зависимости согласно состоянию backend и пакет проекта:

```bash
python -m pip install -r requirements.lock
python -m pip install --no-deps -e .
```

Подготовить подтверждённую конфигурацию, импортированные данные, архив и сохранённые выпуски. В PowerShell задать:

```powershell
$env:TWINTURBO_CONFIG = 'configs/site.yaml'
# Необязательно для просмотра; нужно для нового расчёта:
# $env:TWINTURBO_PREDICTOR = 'реальный_модуль:фабрика_модели'
python -m streamlit run app.py
```

На экране переключиться в **Проверка на истории** (`replay`) или **Прогноз для сдачи** (`submission`). Без конфигурации сервис недоступен; без сохранённых выпусков каталог пуст. Если модель не подключена, просмотр сохранённых результатов доступен, а кнопка расчёта отключена. В качестве альтернативы оператор может задать `TWINTURBO_SERVICE_FACTORY=module:factory`, возвращающую настроенный `ForecastService`. Это доверенная настройка окружения, не поле для ввода произвольного кода в браузере.

Карточки подключения показывают сведения сервиса о датасетах, модели и погоде; нажатие раскрывает пояснение. Статус погоды не подтверждает наличие кэша на новый момент — его проверяет сервис при расчёте. **Календарь** открывает только даты с сохранёнными выпусками, **Следующий выпуск** переключает на следующую запись. **Рассчитать прогноз** отдельно запрашивает момент в UTC и горизонт 24/48 часов; после успеха открывается полученный выпуск. Первый расчёт доступен и при пустом каталоге, если сервис передал турбины и подключена обученная модель. В демо расчёт отключён. На вкладке **Сравнение** показаны две линии на общих часах и раскрываемая таблица точных значений.

Существующий сервис уже предоставляет `list_forecasts`, `get_forecast`, `create_forecast`, `compare_forecasts`, `events`, `export`. Метод `get_display_context(forecast_id, as_of=...)` возвращает сохранённую погоду выпуска и только доступные к моменту просмотра факты. Для старых выпусков без сохранённой почасовой погоды поле остаётся пустым. Спецификация и точные поля: [интеграция UI](docs/UI_INTEGRATION.md). UI не читает `store`, сырые CSV или погодный кэш напрямую.

Дистрибутив называется `TwinTurbo.ai`. Импорты `windoracle` и `TwinTurbo.ai` используют одни и те же классы; работают `python -m windoracle` и `python -m TwinTurbo.ai`. Основная реализация находится в `src/TwinTurbo.ai`.

## Реальный расчёт из CSV

После установки зависимостей и `python -m pip install --no-deps -e .`:

```powershell
python -m windoracle ingest --turbine-1 data/raw/turbine_1.csv --turbine-2 data/raw/turbine_2.csv
python -m windoracle weather fetch --origin 2026-01-15T18:00:00Z --run 2026-01-15T12:00:00Z --progress
python -m windoracle train --origin 2026-01-15T18:00:00Z --output artifacts/models/model.json
$env:TWINTURBO_MODEL_ARTIFACT = 'artifacts/models/model.json'
python -m windoracle predict --origin 2026-01-15T18:00:00Z --predictor windoracle.models.registry:load_predictor --output outputs/forecast
python -m windoracle verify --input outputs/forecast
python -m windoracle export --input outputs/forecast --output outputs/forecast.csv
$env:TWINTURBO_CONFIG = 'configs/site.example.yaml'
$env:TWINTURBO_PREDICTOR = 'windoracle.models.registry:load_predictor'
python -m streamlit run app.py
```

Дата в примере — проверенный запуск из диапазона CSV; CLI принимает любой подготовленный origin. В UI выбрать **Проверка на истории**. Для Linux переменные задаются через `export NAME=value`. В примере UTC и начало интервала — явно отмеченные допущения исходного времени, а не подтверждённые сведения организаторов. Результат не является доказательством точности модели на всём периоде.

## Временной контракт и единицы

- Использованные входы доступны не позднее `origin_time`; время инициализации погодного run не равно времени его публикации.
- Интерфейс проверяет метки доступности погоды и активации модели, скрывает незавершённые и ещё недоступные фактические часы.
- Все временные метки timezone-aware; на экране явно указано **UTC**. Часовой пояс исходного CSV должен подтвердить владелец данных.
- Мощность отображается в **нормализованных единицах**. UI не переводит её в МВт/МВт·ч и не суммирует две турбины без подтверждённых номиналов.
- Q10–Q90 — готовые квантили модели; интерфейс не создаёт интервалы, метрики или «процент доверия AI».
- Advisor описывает известные значения и ограничения. Он не приписывает отклонения обледенению, неисправности или ограничению диспетчера без доказательств.
- Анимация вращения и сезонное оформление иллюстративны: они не являются измерениями RPM, снежного покрова или состояния оборудования.

## Проверки

```bash
python -m unittest tests.test_ui_contract -v
```

Тесты проверяют временную доступность, нулевые/отсутствующие значения, интервалы, точное содержимое экспорта, запрет fixture в рабочем режиме, сравнение выпусков, ошибки и совместимость адаптера с формой `ForecastResult`. Для общего backend-набора после установки зависимостей: `python -m pytest -q`.

В браузере проверены выбор турбины и горизонта, дата/сезон, доступный факт, сравнение, отказ и повтор запроса, переключение режимов, адаптивность на ширине 390 px. Подробный протокол: [UI verification](docs/UI_VERIFICATION.md).
